Breakpoints, states and conditions

Components whose CSS changes at a breakpoint, in a state or under a condition, to try how Pilot edits on top of them. The window is — wide: —.

Padding at breakpoints

Edit its padding without the width chip: from 768px a breakpoint wins, and the edit doesn't show.

.demo-card { padding: 16px; }
@media (min-width: 768px)  { .demo-card { padding: 32px; } }
@media (min-width: 1200px) { .demo-card { padding: 48px; } }
.demo-button { background: var(--color-brand); }
.demo-button:hover { background: #4f46e5; }
.demo-button:focus-visible { outline: 3px solid var(--color-accent); }
.demo-button:active { transform: translateY(1px); }
Click to toggle data-checked 
.demo-dot { margin-left: 2px; background: #cbd5e1; }
.demo-toggle[data-checked] > .demo-dot { margin-left: 22px; background: #fff; }

Nested breakpoint

The media query is nested inside its rule, as CSS nesting writes it.

.demo-nested {
  padding: 12px;
  @media (min-width: 900px) { padding: 28px; }
}

Utility classes

p-4 md:p-8, written as Tailwind v4 does, in a layer.

@layer utilities {
  .u-p-4 { padding: 16px; }
  .u-md-p-8 { @media (width >= 768px) { padding: 32px; } }
}
